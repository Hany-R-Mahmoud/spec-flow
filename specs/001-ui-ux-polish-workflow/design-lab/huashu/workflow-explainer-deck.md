# Workflow Explainer Deck: SpecFlow AI

**Skill**: Huashu Design  
**Format**: deck outline for future HTML/PDF deck  
**Purpose**: explain the SaaS workflow without turning the app into marketing UI.

## Slide 1 - What SpecFlow AI Is

SpecFlow AI turns rough product input into implementation-ready specs, PRDs,
epics, stories, readiness checks, review loops, and export packages.

Visual:

- App shell frame.
- Flow strip: Intake -> Clarify -> PRD -> Epics -> Stories -> Quality -> Review
  -> Export.

## Slide 2 - Current Prototype Strength

The current Replit-generated app already has the right workflow bones:

- Dashboard.
- New breakdown intake.
- Workflow phase workspace.
- Reviews.
- Exports.
- Settings.

Visual:

- Six app sections as compact tiles.
- Baseline screenshot reference.

## Slide 3 - Main Product Gap

Prototype is interactive but not yet trustable as a real product:

- Mock data.
- Visual-only command search.
- Missing Projects route.
- Health-only API.
- No persistence.
- Stubbed AI generation.

Visual:

- Product maturity ladder: Prototype UI -> Skeleton completion -> Persistence
  -> AI workflow -> Integrations -> Collaboration.

## Slide 4 - Approved Design Direction

Recommended first direction: **Precision Ops**.

Why:

- Fits dev-tool SaaS.
- Preserves useful density.
- Low implementation risk.
- Fixes hierarchy and accessibility first.

Visual:

- Color tokens, card sample, nav active state, command trigger.

## Slide 5 - First Implementation Slice

Start with shell/dashboard foundation:

- Accessible command trigger.
- Labeled nav and icon buttons.
- Stronger active nav state.
- KPI semantic accents.
- Table caption/name.
- Empty states.

Visual:

- Before/after annotations on dashboard regions.

## Slide 6 - What Not To Change Yet

Do not:

- Redesign the product IA.
- Add marketing hero patterns.
- Add backend/API changes in UI polish slice.
- Add dependencies for visual polish.
- Blend all design directions into one.

Visual:

- Guardrail list next to scoped implementation box.
