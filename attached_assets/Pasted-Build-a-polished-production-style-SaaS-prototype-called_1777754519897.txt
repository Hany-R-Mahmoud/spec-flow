Product:
SpecFlow AI is an AI-guided product breakdown workspace for Product Managers and Product Owners. It turns messy product input into structured PRDs, epics, developer-ready Jira user stories, quality checks, developer review, and Jira-ready export.

Core workflow:
Intake → Clarification → PRD → Epics → Stories → Quality Review → Developer Review → Jira Export

Primary users:
- Product Managers
- Product Owners

Secondary users:
- Developers
- Engineering leads
- QA
- Designers

Core problem:
PMs and Product Owners often start from rough product ideas, stakeholder requests, meeting notes, transcripts, or incomplete PRDs. They then struggle to create proper epics and user stories that match business requirements and are actually feasible for developers. This causes repeated developer revisions, unclear backlog handoffs, and delayed story execution.

Core promise:
Turn messy product requirements into PRDs, epics, and developer-ready Jira stories through a guided workflow with clarification questions, quality scoring, developer review, and export-ready backlog output.

Use this constitution:

# SpecFlow AI Constitution

## Product Purpose
SpecFlow AI exists to help Product Managers and Product Owners turn messy product input into structured PRDs, epics, developer-ready Jira user stories, quality checks, developer review, and Jira-ready export.

Prioritize backlog clarity, developer readiness, and traceability over generic AI writing.

## Workflow Principle
The product must follow:
Intake → Clarification → PRD → Epics → Stories → Quality Review → Developer Review → Jira Export

Each phase must have:
- visible status
- editable artifact
- next action
- quality or missing-context feedback where relevant

The app must not behave like a generic chatbot.

## Clarification Before Generation
The app must not blindly generate final Jira-ready stories from incomplete requirements.

When required context is missing, show clarification questions grouped by:
- business goal
- target users/personas
- scope and non-goals
- UX/design
- edge cases
- error handling
- localization
- technical constraints
- dependencies
- analytics/tracking
- risks

## Developer Readiness
Every generated story must include a developer-readiness score out of 100.

Score dimensions:
- clarity: 20
- acceptance criteria: 20
- business alignment: 15
- technical feasibility: 15
- testability: 10
- edge cases/error handling: 10
- dependencies/design/localization: 10

Score labels:
- 90-100: Ready for Jira
- 75-89: Minor review needed
- 60-74: Needs PM refinement
- Below 60: Not ready

## Jira-Ready Output
Every exported story must include:
- issue type
- summary
- description
- acceptance criteria
- priority
- labels
- components
- dependencies
- reviewer status
- readiness score

Do not implement real Jira API integration. Provide copy-ready Markdown, CSV preview, and JSON preview. “Connect Jira” may appear as disabled/coming soon.

Technical stack:
Use a modern React + TypeScript app. Prefer Vite if no framework is already selected. Use Tailwind CSS. Use shadcn/ui-inspired components where practical. Use lucide-react icons where useful.

Do not implement real AI API calls yet. Simulate AI behavior with deterministic mock generation functions and realistic sample outputs. Structure the app so real AI can be plugged in later.
